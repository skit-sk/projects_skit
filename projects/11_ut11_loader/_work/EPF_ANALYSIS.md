## `ВнешняяОбработка10_3v103.epf` — модуль объекта

**Файл (в проекте):** `_work/ВыгрузкаДанныхВXML_10_3_obj.bsl` (647 строк)

### Входные параметры
```
ВыполнитьВыгрузку(пДатаОстатков, пОрганизация, пСклад, пИмяФайла)
```

### Что выгружает

| Сущность | Источник УТ 10.3 | XML-тег |
|----------|------------------|---------|
| Склады | `Справочник.Склады` | `<Справочник_Склады>` |
| Типы цен | `Справочник.ТипыЦенНоменклатуры` | `<Справочник_ТипыЦен>` |
| Единицы измерения | `Справочник.КлассификаторЕдиницИзмерения` | `<Справочник_ЕдиницыИзмерения>` |
| Номенклатура (с группами) | `Справочник.Номенклатура` + вид | `<Справочник_Номенклатура>` |
| Штрих-коды | `РегистрСведений.Штрихкоды` | атрибут `ШтрихКод` |
| Остатки | `РегистрНакопления.ТоварыОрганизаций.Остатки` | атрибут `Количество` |
| Себестоимость | `РегистрНакопления.ПартииТоваровНаСкладах.Остатки` | `<Себестоимость>` |
| Цены | `РегистрСведений.ЦеныНоменклатуры.СрезПоследних` | `<Цена_<КодТипаЦены>>` |

### Формат XML

```xml
<?xml version="1.0" encoding="utf-8"?>
<Элемент>
  <Справочник_Склады>
    <Элемент ИмяЭлемента="UUID" Код="000000001" Наименование="..."/>
    ...
  </Справочник_Склады>
  <Справочник_ТипыЦен>
    <Элемент ИмяЭлемента="UUID" Наименование="..."/>   <!-- БЕЗ Код! -->
    ...
  </Справочник_ТипыЦен>
  <Справочник_ЕдиницыИзмерения>
    <Элемент ИмяЭлемента="UUID" Код="..." Наименование="..."/>
    ...
  </Справочник_ЕдиницыИзмерения>
  <Справочник_Номенклатура>
    <Элемент ИмяЭлемента="UUID" Код="..." Наименование="..." НаименованиеПолное="..."
             Родитель="UUID" ЭтоГруппа="true|false" СтавкаНДС="..."
             ЕдиницаИзмерения="..." ВидНоменклатуры="..." ШтрихКод="..." Количество="0">
      <Себестоимость>0</Себестоимость>
      <Цена_<КодТипаЦены>>0</Цена_<КодТипаЦены>>
      ...
    </Элемент>
    ...
  </Справочник_Номенклатура>
</Элемент>
```

⚠️ **Важно:** в `Справочник_ТипыЦен` атрибут `Код` НЕ пишется (см. строку 458
исходника `ЗаписатьСправочникТиповЦен()`). Это **баг исходной обработки** —
без `Код` epf2 не может сопоставить «1 Оптовая» с правильным видом цены.

## `ЗагрузкаДанныхИзXML_V013.epf` — модуль формы

**Файл (в проекте):** `_work/ЗагрузкаДанныхИзXML_V013_form.bsl` (4032 строки)

### Версия 1.72 (15.01.2026) — последняя

Полностью покрывает:
- **Парсинг XML** (SAX, потоково, оптимизирован)
- **Загрузку номенклатуры** в УТ 11 (с группами, видами, ставками НДС, ед.изм.)
- **Создание документа `ВводОстатковТоваров`** с пересчётом упаковок
- **Создание документа `УстановкаЦенНоменклатуры`** (с диагностикой движений)
- **Запись штрих-кодов** в существующую номенклатуру
- **Логирование** в файл и в окно сообщений

### Маппинг цен, зашитый в epf2 (строки 2068-2073)

```1c
Если РодительскийТег = "Цена_Закупочные" ИЛИ РодительскийТег = "Цена_000000001" Тогда
    ТекущиеДанные.Закупочные = ЗначениеЦены;
ИначеЕсли РодительскийТег = "Цена_Опт1" ИЛИ РодительскийТег = "Цена_000000004" Тогда
    ТекущиеДанные.Опт1 = ЗначениеЦены;
ИначеЕсли РодительскийТег = "Цена_Розница" ИЛИ РодительскийТег = "Цена_000000005" Тогда
    ТекущиеДанные.Розница = ЗначениеЦены;
КонецЕсли;
```

**Жёстко прописанные соответствия:**
- `Цена_000000001` / `Цена_Закупочные` → вид цены «Закупочная»
- `Цена_000000004` / `Цена_Опт1` → вид цены «Оптовая»
- `Цена_000000005` / `Цена_Розница` → вид цены «Розничная»

В нашем XML **нет `Цена_000000004`** — есть `000000002` и `000000003`, которые
не распознаются как оптовая. См. `MIGRATION_MAP_UT10_UT11.md` — раздел
«Сопоставление типов цен».

### Создаваемые виды цен (строки 3313-3346)

Если в базе УТ 11 нет видов цен, epf2 создаёт их по наименованию
(«Закупочная», «Оптовая», «Розничная»). У остальных наших типов цен
(«1 Оптовая», «2 Монтажники», «3 Колонка», «4 Колонка», «5 Розничная»,
«Закупочная+5», «Розничная +10%») — **не создаёт и не загружает**.

## Что нужно адаптировать для нашего переноса

### 1. Выгрузка (epf1 → поправить)
- ✅ **Дописать атрибут `Код`** в `ЗаписатьСправочникТиповЦен()` —
  без него epf2 не сопоставит «1 Оптовая» с «Оптовая».
- ✅ **Дописать выгрузку контрагентов** (если нужны) — добавить
  раздел `Справочник_Контрагенты` в `ВыполнитьВыгрузку()`.

### 2. Загрузка (epf2 → расширить)
- ✅ **Расширить маппинг цен** на коды `000000002`, `000000003`,
  `УТ0000001`, `УТ0000002`, `УТ0000003`, `УТ0000005` —
  через пользовательскую таблицу соответствий «код XML → вид цены УТ 11».
- ✅ **Добавить создание видов цен** для «Монтажники», «Колонка»,
  «Закупочная+5», «Розничная +10%» — сейчас epf2 их не создаёт.

### 3. Документ ввода остатков
- ✅ **Разделить остатки по организациям** — наша выгрузка делает это по
  одному `пОрганизация`, но в XML 1 организация неявно.
- ✅ **Разделить по складам** — epf1 принимает 1 склад, epf2 — тоже 1.
  Если остатки нужны на 2 складах, выгрузку нужно делать дважды.

## Версии и совместимость

- epf1: версия 8.2 (obj_version 802), обычные формы, УТ 10.3
- epf2: версия 8.3.x, управляемые формы, УТ 11.5
- Совместимость формата XML между ними — **полная** для номенклатуры,
  остатков, себестоимости. Частичная — для цен (из-за пустого `Код` в
  `Справочник_ТипыЦен`).
