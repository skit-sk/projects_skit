# Preflight — строгая проверка перед релизом EPF

## Когда использовать

- При запросе «выпустить релиз», «собрать epf», «проверить epf»
- При любой жалобе на «Ошибка формата потока»
- Перед выдачей `.epf` файла пользователю

## Команда

```bash
./scripts/preflight.sh <build_dir> <output.epf>
```

Пример:
```bash
./scripts/preflight.sh \
    projects/11_ut11_loader/_work/build_v200 \
    projects/11_ut11_loader/_work/ЗагрузкаДанныхИзXML_V021_UT11_v2.02.epf
```

## 7 этапов верификации

| Этап | Что проверяет | Ошибка → причина |
|------|--------------|-----------------|
| 1. `verify_elem_strict.py` | Дубликаты name/id, битые data-ссылки, None в raw | Ошибка формата потока |
| 2. `v8unpack -B` | Сборка EPF из исходников | Синтаксическая ошибка BSL |
| 3. `v8unpack -E` | Распаковка готового EPF | **Формат потока** (контейнер повреждён) |
| 4. `verify_elem_strict.py` (unpack) | Те же проверки на распакованном | Скрытые дефекты метаданных |
| 5. Roundtrip diff | Form после пересборки совпадает с эталоном | v8unpack переписывает raw-данные |
| 6. `verify_epf.py` | Паттерны BSL + регрессии | Утеряна функциональность |
| 7. Сигнатура | Первые 4 байта `ff ff ff 7f` | Невалидный контейнер |

## Типовые ошибки и исправления

### ❌ «Ошибка формата потока» в 1С

1. **Запустить preflight** → узнаешь точную причину
2. **Дубликат колонки в таблице** → удалить дубликат из `child[]`
3. **data-запись ссылается на несуществующий prop** → исправить `raw[12]`
4. **None/null в raw** → найти и заменить на корректное значение
5. **Roundtrip diff не совпадает** → откатить изменения Form.elem.json, делать всё через BSL

### ❌ v8unpack ругается на сборку

1. **Синтаксис BSL** — проверить `&НаСервере`/`&НаКлиенте`, непарные скобки
2. **Отсутствует data-запись** — добавить для элемента, если он в tree
3. **Битая ссылка в ExternalDataProcessor.json** — проверить `form1` UUID

## Правила работы с Form.elem.json

- **НИКОГДА** не редактировать `raw[]` массивы через `json.load/dump` 
  (кроме безопасных верхнеуровневых: `props[]`, `child[]`, `tree[]`, `data[][]`)
- **НЕ копировать** data-записи между разными типами полей (число→строка)
- Всегда запускать `verify_elem_strict.py` после любых правок
- Если preflight шаг 5 (roundtrip) упал — **откатить** изменения Form.elem.json

## ⚠️ 1C/EPF — СТРОГОЕ ПРАВИЛО ВРЕМЕННЫХ ДИРЕКТОРИЙ

Все временные файлы операций с 1С EPF (распаковка, сборка, верификация)
создавать ТОЛЬКО в:

```
projects/11_ut11_loader/_work/.tmp/
```

❌ **ЗАПРЕЩЕНО** использовать глобальную `/tmp/` для любых операций 1С EPF.

✅ `scripts/preflight.sh` и `_work/verify_epf.py` уже настроены на `_work/.tmp/`.
   При ручном запуске v8unpack для проверки указывать ту же директорию:

```bash
v8unpack -E ЗагрузкаДанныхИзXML_V021_UT11_v2.02.epf _work/.tmp/check
```

Очистка: `.tmp/` удаляется при каждом запуске preflight/verify.  
Принудительно: `rm -rf projects/11_ut11_loader/_work/.tmp/`.
